# 데이터 구조와 일정 규칙

현재 기준은 SQLite schema v8, EventFlow v0.3.29다. 컬럼 이름은 database.py CREATE TABLE이 최종 근거다.

## 핵심 데이터

- `events`: 행사명, 시작일, 종료일, 장소(`location`), 주최/주관(`organizer`), 예산, `budget_tax_mode`, `pm_vendor_id`
- `master_items`: 기본 항목과 확인 포인트·수량·단위·기본 단가·기본 VAT·기본 업체·기본 담당. 기준일·오프셋 컬럼은 없다
- `event_tasks`: 행사 생성 시 복사한 항목 스냅샷과 실제 진행 데이터
- `contacts`: `kind`, `name`, `phone`, `job_title`, `role_note`, `company_id`. 이메일 컬럼은 없다
- `settings`: 앱 설정 key-value
- `event_vendors` / `event_freelancers`: 행사 참여 업체·프리랜서

## 현재 일정 규칙

- 새 업무의 시작일·마감일은 비운 채로 만든다. 행사일에서 자동 계산하지 않는다.
- 사용자가 체크리스트에서 날짜를 입력하거나 비운다.
- `planned_start`와 `due_date`가 모두 있으면 시작일 ≤ 마감이어야 한다.
- 달력과 임박/지연 집계는 필요한 날짜가 있는 업무만 대상으로 한다.
- 행사 날짜를 바꿔도 기존 업무 날짜는 다시 계산하지 않는다.

## 폐기된 과거 규칙 (v0.3.25 / DB v7 이전)

아래 규칙은 더 이상 코드에 없다. 역사 기록으로만 둔다.

## (폐기) 일정 필드

- 기준일 `START`: 최종 행사일 기준 사전·행사 업무
- 기준일 `END`: 최종 행사일 기준 사후 업무
- `start_offset`: 기준일에 더할 작업 시작일 상대 일수
- `due_offset`: 기준일에 더할 마감일 상대 일수
- 최종 행사일을 별도로 입력하면 준비 시작일~최종 행사일을 가용 준비 기간으로 사용한다.
- 기본 일정표의 최대 준비 기간은 D-120이다. 가용 준비 기간이 120일보다 짧으면 음수 오프셋을 같은 비율로 압축해 준비 시작일보다 앞서지 않게 한다.
- 양수 오프셋의 사후 업무는 압축하지 않고 최종 행사일 이후에 배치한다.
- 최종 행사일을 별도로 입력하지 않으면 준비 시작일을 행사일로 사용해 기존 D-Day 오프셋을 그대로 계산한다.
- 수동 날짜 편집 시 `schedule_mode=manual`로 바뀐다.

## 기본 오프셋 작성 원칙

| 업무군 | 권장 작업기간 |
|---|---|
| 운영 행정·허가·보험 | D-120~D-14 |
| 행사 기획·출연·프로그램 | D-90~D-7 |
| 홍보 기획·제작·집행 | D-75~D-3 |
| 시스템·시설 발주·확정 | D-60~D-3 |
| 운영 인력·비품 | D-30~D-1 |
| 현장 설치·리허설 | D-3~D-1 |
| 기록 | D-1~D+7 |
| 결과보고 | 행사 종료일 D+1~D+30 |

세부 120개 값은 `tools/build_seed_data.py`에서 명시적인 키워드·분류 규칙으로 생성하고 `resources/master_items.json`에 기록한다. 기본 항목 화면에서 사용자가 수정할 수 있다.

## (폐기) 재계산

- 행사 날짜 변경 시 `auto` 작업만 새 기준일로 계산한다.
- `manual` 작업은 날짜를 유지한다.
- v2 데이터베이스는 v3로 이전할 때 안전 복사본을 만든 뒤 자동 일정만 새 규칙으로 재계산한다.
- 시작일이 마감일보다 늦어지는 입력은 거부한다.
- 진행률에서 `해당없음`은 제외한다.
