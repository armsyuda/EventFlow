# Codex 작업 연속성

## 프로젝트 목적

Windows 10/11에서 한 사람이 행사별 준비 업무를 관리하는 Python/PySide6 데스크톱 앱이다. 행사명과 날짜로 기본 업무의 작업기간·마감일을 생성하고 체크리스트, 진행률, 달력, 백업·내보내기를 제공한다.

## 2026-08-10 구현 결과

- `01_Contents`의 CSV 118개 항목을 기준으로 `카메라다이`, `콘솔다이`를 추가해 120개 기본 항목을 생성했다.
- 반복 오염값 `81`, `#NAME?` 및 기존 행사 데이터는 가져오지 않았다. 원본 파일은 수정하지 않았다.
- `02_Planning`에 8개 단계별 계획·설계 문서를 작성했다.
- `03_Program`에 PySide6 UI, SQLite 저장, 일정 엔진, 백업·복원, Excel/CSV 내보내기와 테스트를 구현했다.
- 행사 생성 시 기본 항목을 스냅샷으로 복사한다. 기본 항목 수정은 기존 행사에 소급되지 않는다.
- 행사 날짜 변경 시 `auto` 일정만 재계산하고 사용자가 날짜를 고친 `manual` 일정은 보존한다.
- SEED는 React 코드를 복사하지 않고 의미 기반 토큰·간격·상태·접근성 원칙을 PySide6 QSS로 재구현했다.
- `새 행사` 창의 인스턴스 변수가 Qt의 핵심 `QObject.event()` 메서드를 가려 Windows 네이티브 충돌이 발생하던 문제를 수정했다. 변수명을 `event_record`로 분리하고 GUI 회귀 테스트를 추가했다.
- 기본 항목 표에 확인 포인트 다음으로 수량, 단위, 업체, 담당을 배치했다. 추가·수정·삭제를 지원하며, 기본 업체·담당도 새 행사 작업에 복사한다.
- 데이터베이스 스키마를 v2로 올렸다. 기존 v1 DB는 실행 시 기본 업체·담당 열을 자동 추가하며, 마이그레이션 전에 안전 복사본을 만든다.

## 2026-08-10 v0.2.0 개선

- 실제 사용자 행사 `2026-08-10~2026-10-02`가 기존 규칙에서 4월부터 시작되던 원인을 확인했다. 시작일을 행사 당일로 보고 D-120을 빼던 의미 불일치가 원인이었다.
- `start_date`를 준비 시작일, `end_date`를 최종 행사일로 명확히 표시하고, 120일보다 짧은 준비 기간은 음수 D-Day 오프셋을 비례 압축한다. 사후 양수 일정은 유지한다.
- DB 스키마 v3에서 기존 자동 일정만 새 규칙으로 재계산한다. 수동 일정은 보존하며 `event_checklist.pre-v2.db` 안전 복사본을 먼저 만든다.
- 대시보드의 파란 교차 줄을 제거하고 지연/임박 업무를 의미 기반 옅은 경고색으로 표시한다.
- 모든 스크롤바, 탭, 표 머리의 빈 영역을 밝은 테마로 통일했다.
- 행사·기본 항목·담당/업체 표는 모든 열 너비를 직접 조정·이동할 수 있고 `열 너비 맞춤`을 제공한다.
- 기본 항목은 더블클릭 대화상자 없이 모든 표시 필드를 표에서 바로 편집한다.
- 달력은 개별 업무 기간을 얇은 다중 박스로 표시하고 우측 목록을 카드형 정보 구조로 재구성했다.
- 자동 테스트 20개 통과. 실제 사용자 DB 복사본 v2→v3 이전, 안전 복사본, 준비 시작일 이전 일정 제거, PyInstaller 배포본 기동과 달력 렌더를 확인했다.

- 최종 배포 전 앱 전용 아이콘과 조직명 결정, Qt 라이선스 배포 문구 확인

## 2026-08-10 v0.2.1 달력 가독성 개선

- 달력의 얇은 기간 박스 안에 작은 글씨의 업무명을 표시한다.
- 날짜별 표시 순서는 미완료 우선, 마감일이 가까운 순서, 우선순위, 기본 순서다.
- 셀에는 최대 네 줄만 사용하며 초과 업무는 `+N개 더보기`로 표시한다. 날짜를 선택하면 오른쪽 카드 목록에는 전체 업무가 그대로 나온다.
- 일정이 많은 날에도 날짜 숫자가 가려지지 않도록 업무가 있는 셀의 날짜를 위쪽에 고정해 다시 그린다.
- 자동 테스트 21개 통과 및 실제 행사 DB 복사본으로 달력 라벨·더보기·전체 우측 목록을 렌더 검증했다.

## 주의사항

- 실제 사용자 DB를 초기화하거나 기본 데이터로 다시 덮어쓰지 않는다.
- 백업 복원 전 현재 DB를 반드시 별도 백업한다.
- 기본 일정표는 일반 행사 기준 초안이며 법정 신고·허가 기한을 보증하지 않는다.
# 2026-08-11 이벤트 플로우 0.3.0

- 앱 명칭은 `이벤트 플로우`, 약칭은 `이플`, 실행 파일은 `EventFlow.exe`다. 사용자 데이터 위치 `%LOCALAPPDATA%\EventCheckList`는 유지한다.
- 메인 메뉴는 대시보드/체크리스트/달력/정산내역/설정이며, 앱은 항상 행사 미선택 상태로 시작한다. 선택 전에는 체크리스트·달력·정산내역이 비활성화된다.
- 기본 Windows 제목 표시줄을 이플 전용 상단바로 교체했고 주황색 `이플` ICO/PNG/SVG를 추가했다.
- DB는 v4다. `master_items` 기준 단가/VAT, `events` 예산 VAT 기준, `event_tasks` 행사 단가/VAT/제외 상태·사유, 업체 소속 담당자와 행사 참여 업체/프리랜서 관계를 저장한다.
- v3 이전 시 기존 `cost`를 수량으로 나눈 행사 단가로 옮기며 `event_checklist.pre-v3.db`를 먼저 만든다. 기존 담당자는 소속 없는 프리랜서로 보존한다.
- 체크리스트는 기본항목 가져오기, 일회성 항목, 다중 제외와 사유, 기존 기록 복원을 지원한다. 같은 행사에 같은 기본항목이 중복 생성되지 않는다.
- 달력은 연속 주간 막대, 대분류별 저채도 색상, 업무명, 동적 Lane, `+N개 더보기`, 전체 우측 목록과 숨김 상태 저장을 지원한다.
- 정산은 공급가 기준 행사 단가, 과세/면세, 원 단위 ROUND_HALF_UP, 대분류 소계/전체 합계, VAT 포함·별도 예산 비교를 지원한다. 해당없음과 제외 항목은 합계에서 빠진다.
- 검증: pytest 25개 통과. 실제 사용자 DB 복사본은 v3→v4 전후 행사 1/업무 120/담당·업체 10/기본항목 120으로 동일했다. 1280×720 정산, 1440×900 달력, 125%·150% 시작 화면을 렌더 확인했다.
- 배포 위치: `03_Program/dist/EventFlow/EventFlow.exe`. 패키징 실행 파일은 신규 DB와 사용자 DB 복사본에서 모두 종료 코드 0으로 기동했다.

## 2026-08-11 이벤트 플로우 0.3.3

- 행사 정보 창의 참여 업체·프리랜서 목록을 편집 화면의 남는 높이에 맞춰 크게 확장했다. 새 행사 화면은 1280×720에서도 기본항목 선택이 가능하도록 목록 비율을 별도로 유지한다.
- 체크리스트와 행사 창의 날짜 입력은 화살표를 없애고 입력칸 클릭 시 전용 달력이 바로 열리게 했다.
- 행사 예산·기준 단가·행사 단가·정산 단가는 증감 화살표를 제거하고 천 단위 쉼표와 `원`을 공통 표시한다.
- 정산 대분류 소계는 연한 주황색, 전체 합계는 주황색 바탕과 굵은 흰색 금액으로 강조한다.
- Git 저장소를 `https://github.com/armsyuda/EventFlow.git`의 `origin`으로 연결하고 Windows 빌드·Release 워크플로를 추가했다.
- 앱 시작 시 공개 GitHub Release를 비동기로 확인한다. 현재 버전보다 높은 태그와 `EventFlow-Windows.zip`이 있으면 상단 업데이트 버튼을 활성화하며, GitHub가 제공하는 SHA-256 digest를 검증한 뒤 앱 폴더를 교체하고 재실행한다. 사용자 DB는 설치 폴더 밖에 있어 유지된다.
- 자동 업데이트에 인증 토큰을 내장하지 않는다. 저장소 또는 Release가 비공개이면 앱에는 `업데이트 확인 불가`가 표시되므로 공개 Release 운영이 필요하다.
- 검증: pytest 30개 통과. 날짜 입력 클릭 시 달력 표시, 금액 쉼표·화살표 제거, Release 버전 비교와 다운로드 digest 검증을 자동 테스트했다.
