# Codex 작업 연속성

## 프로젝트 목적

Windows 10/11에서 한 사람이 행사별 준비 업무를 관리하는 Python/PySide6 데스크톱 앱이다. 기본 업무는 날짜 없이 생성하며 사용자가 체크리스트에서 작업기간·마감일을 직접 입력한다. 진행률, 달력, 백업·내보내기를 제공한다.

## 2026-08-13 Supabase 최소 연결 확인

- `JMT Event Flow` Supabase 프로젝트(`ap-northeast-2`)가 정상 상태이며 프로젝트 URL과 공개용 publishable key로 Auth 설정 API가 HTTP 200을 반환하는 것을 확인했다. 이메일 인증은 활성화되어 있고 `public` 테이블은 아직 없다.
- 앱에는 로그인 UI나 원격 데이터 저장을 연결하지 않고, 환경변수 `EVENTFLOW_SUPABASE_URL`과 `EVENTFLOW_SUPABASE_PUBLISHABLE_KEY`를 읽어 연결만 검사하는 `supabase_connection.py`와 검사 도구를 추가했다. 실제 키는 소스와 문서에 저장하지 않았다.
- Supabase 연결 단위검사 3개 및 실제 서버 검사가 통과했다. 전체 pytest는 기존 편집 상태의 `event_checklist.export`에 `export_csv`가 없어 수집 단계에서 중단됐으며 이번 작업에서는 해당 코드를 변경하지 않았다.
- 다음 단계는 회사·멤버·초대 구조 확정, Auth 로그인 UI, RLS가 적용된 원격 스키마 순서다. 관리자용 secret/service-role 키는 데스크톱 앱에 포함하지 않는다.

## 2026-08-12 v0.3.25 자동 일정 완전 제거

- 새 행사와 `기본 항목 가져오기`로 생성되는 모든 업무의 작업 시작일·마감일은 `NULL`로 시작한다. 행사 준비 시작일과 최종 행사일을 업무 날짜에 복사하지 않는다.
- 체크리스트의 빈 날짜는 `미입력`으로 표시한다. 날짜 셀을 눌러 직접 입력할 수 있고 셀 편집기의 `지우기`로 다시 빈 값으로 만들 수 있다.
- 기본 항목 원본 JSON과 DB에서 `anchor`, `start_offset`, `due_offset`을 제거했다. 행사 업무 DB에서도 해당 열과 `schedule_mode`를 제거하고 자동 일정 계산 모듈과 화면의 D-Day 표기를 제거했다.
- 날짜가 하나라도 없는 업무는 달력, 지연 업무와 7일 이내 마감 목록에서 제외한다. 시작일과 마감일이 모두 입력된 업무만 달력에 표시한다.
- DB 스키마는 v7이다. 기존 행사에 이미 저장된 업무 날짜는 사용자 데이터 보호를 위해 보존하고, 자동 일정 관련 열만 제거한다. 이전 전에 `event_checklist.pre-v6.db` 안전 복사본을 만든다.
- 자동검사 75개 통과. 실제 사용자 DB 복사본의 기존 업무 121개를 유지한 채 v7 이전과 외래키 검사를 통과했고, 새 검증 업무 3개가 모두 빈 날짜로 생성됐다. 패키징 실행 파일도 실제 DB 복사본 이전 및 smoke test 종료 코드 0을 확인했다.
- 확인용 실행 파일은 `03_Program/EventFlow_Current/EventFlow.exe`, 설치 파일은 `03_Program/EventFlow_Installer/EventFlow-Setup-0.3.25.exe`다. 설치 파일은 코드 서명되지 않았다.

## 2026-08-12 체크리스트 날짜 달력 표시 수정

- 빈 날짜를 되돌리는 `지우기` 버튼을 좁은 표 셀 안에 날짜 입력칸과 함께 넣어 서로 겹치던 UI 문제를 수정했다.

## 2026-08-12 PM 담당·직접 일정·정산 선택 개선

- 기본 설정에서 일정 기준과 시작/마감 D-Day 열을 제거했다. 새 업무의 날짜는 행사 기간으로 초기화되며 행사별 체크리스트에서 사용자가 직접 입력한다. 기존 업무 날짜는 행사 날짜를 바꿔도 자동 재계산하지 않는다.
- 행사 정보에 `PM 업체`를 추가했다. 체크리스트는 `마감일 → 담당자(PM) → 업체 → 업체담당자 → 업체담당자 전화번호` 순서이며, PM 담당자는 행사 PM 업체 소속 사람만 선택할 수 있다. 업체담당자도 선택 업체 소속으로 제한되고 전화번호는 자동 표시된다.
- 체크리스트에서 D-Day, 일정, 행사 단가 열을 제거했다. 기존 담당자 값은 업체담당자로 유지하며 새 PM 담당자 값은 별도 저장한다.
- 정산내역은 설정에 등록한 전체 업체를 즉시 선택 목록에 표시하고, 각 대분류 안의 중분류 `기타`를 마지막에 정렬한다.
- DB 스키마는 v6이다. 기존 DB에는 `events.pm_vendor_id`, `event_tasks.pm_assignee_id`만 추가하며 기존 사용자 데이터는 보존한다.
- 자동검사 78개 통과. 실제 사용자 DB 복사본은 행사 1개와 업무 121개를 유지한 채 v6 이전에 성공했고, 소스와 확인용 실행 파일 smoke test 모두 종료 코드 0이었다.
- 설치본은 만들지 않았다. 현재 확인용 파일은 `03_Program/EventFlow_Current/EventFlow.exe`이다.

## 2026-08-12 체크리스트 연락처·분류 정렬 수정

- 재실행 시 `UNIQUE constraint failed: contacts.kind, contacts.name`로 시작하지 못한 원인은 초기화 과정이 폐기된 이름 단독 고유 인덱스를 다시 만들던 순서 오류였다. 연락처는 ID로 구분하고 이름 중복을 허용하며, 조회용 비고유 인덱스만 유지한다.
- 체크리스트 업체·담당자 선택 목록은 행사 참여자로 미리 지정된 연락처뿐 아니라 설정에 등록된 전체 연락처를 즉시 읽는다. 동명이인은 `이름 · 소속 업체` 또는 `이름 · 프리랜서`로 구분한다.
- 체크리스트 열을 `업체 → 담당` 순서로 인접 배치했다.
- 체크리스트와 기본 항목은 마감일이나 마지막 추가 순서 때문에 분류가 흩어지지 않도록, 기존 최초 순서를 유지하면서 대분류→중분류→항목 순으로 모은다. 새 항목도 선택한 분류 안에 배치되어 대분류와 중분류 세로 병합이 한 덩어리로 유지된다.
- 자동검사 75개 통과. 실제 사용자 DB 복사본 시작 검사와 별도 실행 파일 smoke test 종료 코드 0을 확인했다.
- 이 수정은 아래 최신 PM·직접 일정 개선에 포함되었으며 현재 확인용 실행 파일은 `03_Program/EventFlow_Current/EventFlow.exe`다.
